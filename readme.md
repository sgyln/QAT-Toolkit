## Repository Overview

This QAT (Quality Assurance Testing) toolkit contains a test case for an AI-generated web application, along with the prompt and code used to produce it.

- **Part A:** `readme.md`: this file, containing the test case for an AI-generated web application
- **Part B:** `webapp-generation-prompt.txt`: the AI prompt used to create the test web application
- **Part C:** `test-webapp.php`: the single-file PHP web application generated by AI

## Test Case Documentation

| Field | Details |
|---|---|
| **Test Case ID** | TC-DataEntry-001 |
| **Title** | Data Entry - Valid |
| **Description** | Functional testing of the Data Entry page with backend validation using MySQL queries |
| **Preconditions** | Kara David Birthday Wishnote App is installed locally and the MySQL database is pre-populated for comparison. The Data Entry page is accessed in the latest Chrome/Firefox browser. |
| **Test Data** | Five (5) valid entries containing First Name, Last Name, Government Position, and Location, each within its maximum character limit |
| **Source File** | `textcase.txt` |

## Test Execution

| Step | Action | Expected Result | Actual Result |
|---|---|---|---|
| a | Verify that the form contains labels in proper order and the text boxes are writable | The form contains labels in this order: "Target's First Name", "Target's Last Name", "Target's Government Position", and "Target's Location"; all text boxes are writable | The form contains labels in this order: "Target's First Name", "Target's Last Name", "Target's Government Position", and "Target's Location"; all text boxes are writable |
| b | Verify the "Send Wish Note" button | The "Send Wish Note" button changes color on hover and is not disabled | The "Send Wish Note" button changes color on hover and is not disabled |
| c | Enter test data on their respective fields | The respective fields accept data entries of valid test data | The respective fields accept data entries of valid test data |
| d | Click "Send Wish Note"; a modal appears | A modal titled "Verify Target Data" appears | A modal titled "Verify Target Data" appeared |
| e | Verify the modal contains the same entry as the test data | The modal shows the same First Name, Last Name, Government Position and Location that were entered | The modal showed the same First Name, Last Name, Government Position and Location that were entered |
| f | Click the Cancel button | The modal closes and the form is not submitted | The modal closed and the form was not submitted |
| g | Click "Send Wish Note" again, then "Confirm & Send" in the modal | The modal's "Confirm & Send" button submits the form | The form was submitted and the entry was saved |
| h | Verify a successful entry message shows on the Data Entry page | The message "Success! The wish note has been sent." appears above the form | The message "Success! The wish note has been sent." appeared above the form |
| i | Verify the test data shows in the database (`SELECT * FROM main_corrupt_politicians;`) | All entered data, including Location, appears in the `main_corrupt_politicians` table | Seven rows were inserted with FirstName, LastName and GovPosition, but Location is NULL in all seven rows (query used: `SELECT * FROM main_corrupt_politicians;`) |

**Status:** Failed (Location is not saved to the database, which is the intentional flaw in `test-webapp.php`)
